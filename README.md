# Найкоротші шляхи на множині перешкод у 2D

Лабораторна робота з курсу «Обчислювальна геометрія та комп'ютерна графіка».
Задача: для множини полігональних перешкод знайти найкоротший евклідів шлях
між запитними точками **S** і **T**.

Метод: **граф видимості + A\*** з лінивим (on-demand) обчисленням сусідів,
рівномірною просторовою сіткою та кешуванням видимості.

## Файли

| Файл | Призначення |
|------|-------------|

## Запуск програми (графічний інтерфейс)

> ⚠️ На цьому Mac (macOS 15.6) Tk 8.5 із системного `/usr/bin/python3` падає
> через відому несумісність. Тому GUI запускається під **Python 3.13 + Tk 9.0**.

Один раз встановити Tk (вже встановлено на цьому комп'ютері):

```sh
brew install python-tk@3.13
```

Запуск інтерфейсу:

```sh
/opt/homebrew/bin/python3.13 shortest_path_2d.py
```

### Як користуватися
- **Малювати перешкоду**: ЛКМ — додати вершину, ПКМ або кнопка «Завершити
  перешкоду» — замкнути полігон (≥ 3 вершини).
- **Поставити S / Поставити T**: ЛКМ задає старт/фініш.
- **Згенерувати (випадково)**: ввести кількість перешкод (напр. 300 → ~1300
  вершин) і натиснути кнопку (автоматичний ввід великої кількості даних).
- **Найгірший випадок (слалом)**: будує замкнену рамку з проходами, що змушують
  шлях зигзагом обходити всі перешкоди (демонстрація для найгіршого вводу);
  число у полі — кількість стін.
- **▶ Знайти найкоротший шлях** (або клавіша Enter): запустити алгоритм.
- **Показати граф видимості**: для сцен ≤ 400 вершин — повний граф (O(n²));
  для 400–3000 вершин — k-найближчий граф (O(n·k), той самий, що бачить
  швидкий режим A\*; будується у десятки разів швидше); понад 3000 вершин
  вимикається (граф був би нечитабельним клубком).
- **Очистити** (або Escape): очистити робочу область.

Режим обирається **автоматично**: для сцен понад 1000 вершин вмикається
*швидкий* режим (лише ~90 найближчих кандидатів → у десятки-сотні разів швидше,
шлях коректний і на <1% довший за оптимум); для менших — *точний* (гарантований
оптимум). Поточний режим видно на панелі.

Праворуч унизу панелі — метрики: кількість перешкод `h`, вершин `n`, режим,
довжина шляху, кількість розкритих вершин і **час запиту (мс)**.

## Перевірка коректності та заміри (без GUI, будь-який Python 3.x)

```sh
python3 shortest_path_2d.py --selftest        # автотести коректності
python3 shortest_path_2d.py --bench 1000       # заміри для 1000 перешкод
python3 shortest_path_2d.py --bench-fast 1500  # точний vs швидкий режим
python3 shortest_path_2d.py --bench-worst 30   # найгірший випадок (слалом)
```

## Сценарій для відеопрезентації
1. Запустити GUI; намалювати кілька перешкод мишкою, поставити S і T, увімкнути
   «Граф видимості», натиснути «Знайти шлях» — пояснити ідею (граф видимості + A\*).
2. Очистити; ввести 300–500 перешкод, «Згенерувати» (понад 1000 вершин),
   «Знайти шлях» — показати час запиту і шлях, що огинає перешкоди (для >1000
   вершин автоматично вмикається швидкий режим — частки секунди).
3. Кілька разів переставити T і повторно запустити — показати швидкість
   повторних запитів (кеш видимості).
